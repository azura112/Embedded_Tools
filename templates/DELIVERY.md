# DELIVERY 模板

> 复制为 `versions/vX.Y/DELIVERY.md`（本仓切换期 = 根目录 `vX.Y开发交付__<slug>.md`，结构沿最近一版交付惯例 + 本模板要素，见 PROCESS.md §15.2）。交付是「声称」，审核方将以 git diff 核验；终态提交后禁改可观测数值（失准走勘误批）。

```markdown
# vX.Y 交付报告
> 填写：执行者（阶段 3 末尾）。

- 对应计划：<PLAN 文件名>
- 交付 commit 范围：<基线hash>..<交付hash>（附 git log --oneline 清单）

## 任务完成情况
| 任务 | 状态 | 说明 |
|---|---|---|

## 偏差记录（计划外的一切改动；无偏差写「无」）
| 偏差 | 原因 | 影响 | 计划面外授权（来源 = REVIEW-rN T-n） |
|---|---|---|---|

## AC 自验记录
| AC | 验证方式 | 结果 |
|---|---|---|

## 未完成项与新发现问题（供审核与下次判定）
## 遗留风险
```

本仓增强要素（沿惯例，非本模板强制）：§7 机制与证据区（含 §7.4 自检表——机读值由 `gatecheck --emit` 生成**逐字粘贴禁重打**，是否适用以当版计划为准）、§8 CO 处置表、已发布文档更正走「修订登记 @<sha>」放行。偏差表第四列（固定列，v2.27 P0-3 增补，`CO-9(v2.26)`）= 评审条件清单驱动的门新增断言/门面变更须在该列显式登记授权链（无该项写「无」），与 `docs/开发计划模板.md` §2「门改动授权通道」条同源；该列同时承载「diff 行数 / fail 计数 / 文件枚举 / 时点差覆盖面」类声称的口径标注（`CO-7(v2.26)` 同族）。
