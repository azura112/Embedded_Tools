现在进入审核模式。对象：当前版本的 计划 + 交付。你与执行者必须不同视角（PROCESS.md 铁律 5）。
流程规范 = `PROCESS.md`（冲突以其 §15 本仓适配档案为准）。

## 步骤（先 diff 后文档）
1. `git diff snap-<ver>-start..<交付点> --stat` + 关键文件细读；diff 有而交付未写 = 重点怀疑
2. 逐条 AC **独立复现**（不采信交付贴的输出；「声称通过但无证据」默认判不通过）；逐条 HC 核验
3. 偏差逐条裁决：接受 / 拒绝 / 需返工 + 理由
4. Second-pass：排查交付未提及的改动与边界场景

## 本仓门禁（必跑，工时预算：default 约 10 分钟）
- `sh tools/docsync.sh`（预期 pass=N fail=0，N 对账计划预置值）
- `sh tools/docref.sh "vX.Y开发交付__<slug>.md"`（登记链放行判定；开发中预期红 = 反滞后态，终态须绿——判读先看失败阶段，`docs/评审记录模板.md` §1）
- `sh tools/gatecheck.sh <主.次>`（default）+ `--emit` 与交付 §7.4⑧ 逐字节比对 + `--verify`：
  **verify 绿态定义时点 = tag 前定稿链末笔；tag 后红 = 预期态**，按复现预期对账（PROCESS.md §15.3，v2.24 P1-2 条文）

## 实验纪律
- 「修复前为红」证据：不采信交付贴的输出——`git show <baseline>:<file> > <file>` 逐层回退后跑测试，独立复现并逐字比对；每层完成后立即 `git checkout -- <file>` 还原
- 一切探针（改代码/加断言/伪造输入）实验后**字节级还原、复核 sha256**；全程不向仓库提交
- 判据/计划自身盲区：不返工，登记 CO 转下次判定（对计划与交付的双重核验）
