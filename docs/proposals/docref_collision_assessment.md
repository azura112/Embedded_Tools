## 1. 问题定义

docref 的**修订登记提取规则**（v2.10 G0 起）：取交付文档中「散文行**且**含修订登记字样」的行，抽出其全部 7–40 位十六进制 token 作为登记项，再逐 token 做**区间校验**（须位于该文档记录终点之后、HEAD 之前）与**存在性校验**。

排除面仅两类：**表格行**（`^\s*|`）与 **``` 围栏行**。因此，**任何恰好同时包含（a）修订登记字样与（b）十六进制 token 的散文行**都会被误捕获为登记项——即使该行的语义与登记无关（证据引用、否定语境自述、转红原文引用等）。误捕获后在**区间校验阶段先行报红**（token 位于记录终点之前 → "越界"），其**失败阶段与红形态均不同于**真正的"未登记实质变更"红。

判读纪律（v2.16 G0-2 已固化进 `docs/评审记录模板.md`）：**先看失败阶段**——"登记含无效 SHA（越界）"= 碰撞形态；"存在未经修订登记的实质变更"= 实质面。

## 3. 形态泛化结论

碰撞面**不限于"引用他人红输出"**：四实例合并可见，触发面 = **任何含修订登记字样与十六进制 token 同行的散文行**，包括：

- 引用/证据行（实例 1–3）；
- **否定语境自述行**（实例 4——文档声明"本版无该机制"时恰恰写出了字样）；
- 以及可以类推的一切形态：变更说明行、勘误叙述行、机制自证行等。

推论：**判据不变，碰撞与作者措辞习惯强相关**——缓解只能靠写作纪律（见 §4-b），根治须动提取规则（见 §4-a）。

## 4. 三选项成本分析

### 选项 a：提取规则变更（根治方向一）

- **内容**：登记提取排除"仅 inline-code 的引用行"或更一般地排除"敏感短语处于否定/引用语境的散文行"（可行的机械形态 = 在现排除面之外追加两类排除：整行仅由 inline code + 连接符构成的行；或引入"登记行必须显式以 `- 修订登记` 列表项开头"的收紧形态）。
- **收益**：根治四实例及类推形态；历史文档的碰撞红随之消解（与选项 c-2 联动）。
- **成本**：① 属门改动——需全套自证（红证据构造 + 三场景矩阵 + 判定反转矩阵：v2.14/v2.15 文档改动前后对照）；② 收紧形态可能改变登记放行语义（须验证 v2.10–v2.17 全部历史登记链在收紧后仍放行）；③ 说明与文档同步面（docref.sh 头注、README checklist、两模板）。
- **风险**：收紧过度会把**合法登记行**误排除（漏放行 → 反向误红）——需以历史五版登记链为回归基准。

### 选项 b：引用围栏惯例化（零工具改动，已部分落地）

- **内容**：把三形态写作纪律推广为强制惯例（v2.17 G0-1 已固化进两模板）。
- **收益**：零工具风险；v2.16 实证有效（该版交付文档经 docref 同款提取机检"裸露 token = 无"）。
- **成本**：依赖作者自律 = **登记机制的固有边界**（门只能发现、不能预防）；新作者/新形态仍可能复发（第五实例的概率不降为零）。
- **定位**：**过渡期缓解**，与 a 互补而非替代。

### 选项 c：红文档累积处置

- **现状**：v2.14/v2.15 文档在后续版本发版点均为红（设计行为 + 碰撞形态混合）；本版（v2.17）预期维持该现状（本版不实施根治）。
- **c-1 冻结终点回填**：把历史文档记录终点改为其自身 tag/定稿提交，使区间校验不再涉及后续版本链——**与"已发布物零触碰"纪律冲突**（回填 = 修改已发布文档），须先评估例外授权形态；成本高、争议面大。
- **c-2 历史文档白名单化**：docref 对"已归档版本的交付文档"跳过区间校验（仅保留 diffstat 对账）——属 docref 形态变更，收益明确（红文档数量不再随版本数线性增长），成本同选项 a（门改动 + 全套自证）。
- **判读成本**：每版需按固化提示分阶段判读，成本 O(红文档数) 线性增长；当前规模（2 份）尚可承受。

## 6. 与"登记载体形态评估"的合并评估

两条目**同族**（均在 docref 形态变更类）：登记载体形态（登记行 token 膨胀的二级载体）与本项（提取规则碰撞）都落在"登记机制的表征与提取"这一面，且**共用同一回归基准**（v2.10–v2.17 登记链 + 历史文档红态）。合并收益：一次门改动窗口同时收敛两问题，自证面可共用（红证据/矩阵只做一次）。

## 7. 建议与排期

- **建议实施窗口：v2.18**，经**评审对话批准**后实施；若批准，推荐执行序 = 选项 a（提取规则收紧）→ 选项 c-2（历史文档口径）→ 选项 b 降级为提示性惯例。
- **实施版义务（预留）**：门改动全套自证 + 历史登记链回归（v2.10–v2.17）+ 判定反转矩阵（v2.14/v2.15 文档前后对照）+ 两模板与 README checklist 同步。
- **不批准时的退路**：维持选项 b（v2.17 已固化的写作纪律）+ 判读提示，第五实例出现则重新触发本评估。
